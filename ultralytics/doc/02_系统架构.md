# 02 系统架构

## 2.1 分层调用链

```text
CLI: yolo / ultralytics
  └─ ultralytics.cfg:entrypoint()
       └─ YOLO / RTDETR / SAM / FastSAM / NAS / YOLOWorld / YOLOE
            └─ engine.Model
                 │  .train() / .val() / .predict() / .export() / .track() / .benchmark()
                 │
                 ├─ task_map → Trainer / Validator / Predictor / nn.TaskModel
                 ├─ Exporter → utils.export.* / nn.backends.*
                 └─ trackers.register_tracker → BYTETracker / BOTSORT / …
```

| 层级 | 职责 | 关键路径 |
|------|------|----------|
| CLI / Cfg | 参数解析、任务/模式分发 | `ultralytics/cfg/` |
| 门面 API | 统一用户接口 | `engine/model.py`, `models/yolo/model.py` |
| Engine | 与具体架构解耦的生命周期 | `engine/` |
| Models | 按家族与任务实现四元组 | `models/` |
| NN | YAML→网络、Head、多后端推理 | `nn/` |
| Data | 数据集、增强、推理源 | `data/` |
| Utils | 损失、指标、绘图、回调 | `utils/` |
| Trackers / Solutions / Hub | 跟踪、应用、云端 | 各自子包 |

## 2.2 task_map 设计

`YOLO.task_map`（`models/yolo/model.py`）为每个 task 提供四元组：

```python
{
  "detect": {
      "model": DetectionModel,
      "trainer": DetectionTrainer,
      "validator": DetectionValidator,
      "predictor": DetectionPredictor,
  },
  # classify / segment / pose / obb / depth / semantic 同理
}
```

`Model._smart_load(key)` 按当前 `self.task` 从 `task_map` 取类并实例化。  
**新增任务的标准路径**：实现 Trainer/Validator/Predictor + `nn/tasks` 中模型类 + `cfg/models` YAML，再挂入 `task_map`。

## 2.3 Model 门面职责

文件：`ultralytics/engine/model.py`

| 方法 | 行为摘要 |
|------|----------|
| `_new(cfg)` | YAML 建新模型：`yaml_model_load` → `guess_model_task` → 构建 TaskModel |
| `_load(weights)` | 加载 `.pt` 或导出格式路径 |
| `predict` / `__call__` | 懒创建 Predictor，返回 `list[Results]` |
| `track` | 注册 tracker 后走 predict（默认更低 conf、batch=1） |
| `val` | 创建 Validator，返回 metrics |
| `train` | 创建 Trainer；支持多数据集；结束后 reload best/last |
| `export` | 调用 `Exporter` |
| `benchmark` | 多格式速度/精度基准 |
| `tune` | Ray Tune 或内置 `Tuner` |
| `calibrate` | **depth** 任务标定 `cal_a/cal_b` |
| `embed` | 倒数第二层特征嵌入 |
| `fuse` / `info` / `save` / `load` | 模型工具 |
| `add_callback` 等 | 生命周期钩子 |

加载来源：本地文件、Ultralytics HUB URL、Triton URL。

## 2.4 YOLO 构造时的“变形”

`YOLO.__init__` 根据文件名/结构自动切换类型：

| 条件 | 结果类型 |
|------|----------|
| stem 含 `-world` | `YOLOWorld` |
| stem 含 `yoloe` | `YOLOE` |
| 末层 head 名为 RTDETR | `RTDETR` |
| 其他 | 普通 `YOLO` |

实现方式：替换 `self.__class__` 与 `self.__dict__`（运行时多态）。

## 2.5 Engine 四大组件关系

```text
                    ┌─────────────┐
                    │    Model    │
                    └──────┬──────┘
           ┌───────────────┼───────────────┬────────────┐
           ▼               ▼               ▼            ▼
     ┌──────────┐   ┌───────────┐   ┌───────────┐ ┌──────────┐
     │ Trainer  │   │ Validator │   │ Predictor │ │ Exporter │
     └────┬─────┘   └─────┬─────┘   └─────┬─────┘ └────┬─────┘
          │               │               │            │
          ▼               ▼               ▼            ▼
     DataLoader      Metrics/Plots    Results     部署文件
     + Loss          + JSON           + 可视化    + AutoBackend
```

- Trainer 内部会创建 Validator 做 epoch 验证。
- Predictor 用 `AutoBackend` 加载 `.pt` 或导出模型。
- Exporter 产出的文件可再被 Predictor/Validator 消费。

## 2.6 CLI 与 TASK / MODE

定义于 `ultralytics/cfg/__init__.py`：

```python
TASKS = {"detect", "segment", "classify", "pose", "obb", "semantic", "depth"}
MODES  = {"train", "val", "predict", "export", "track", "benchmark"}
```

默认模型映射 `TASK2MODEL`：

| Task | 默认权重 |
|------|----------|
| detect | `yolo26n.pt` |
| segment | `yolo26n-seg.pt` |
| classify | `yolo26n-cls.pt` |
| pose | `yolo26n-pose.pt` |
| obb | `yolo26n-obb.pt` |
| depth | `yolo26n-depth.pt` |
| semantic | `yolo26n-sem.pt` |

默认数据集：`TASK2DATA`（如 `coco8.yaml`、`cityscapes8.yaml`、`depth8.yaml`）。  
默认指标：`TASK2METRIC`（mAP / accuracy / delta1 / mIoU）。

入口脚本（`pyproject.toml`）：

```toml
yolo = "ultralytics.cfg:entrypoint"
ultralytics = "ultralytics.cfg:entrypoint"
```

## 2.7 配置流

```text
cfg/default.yaml  (DEFAULT_CFG)
       +
  CLI / Python overrides
       ↓
  get_cfg() / check_cfg() / _handle_deprecation()
       ↓
  Trainer / Validator / Predictor / Exporter.args
```

用户全局设置：`SettingsManager` → `~/.config/Ultralytics/settings.json`  
（`datasets_dir`、`weights_dir`、`runs_dir`、`api_key` 等）。

## 2.8 回调（Callbacks）

训练/验证/预测/导出过程中触发事件，如：

- `on_pretrain_routine_end`
- `on_train_start` / `on_train_epoch_start` / `on_train_batch_end`
- `on_fit_epoch_end` / `on_model_save`
- `on_predict_start` / `on_predict_postprocess_end`（跟踪器挂接处）
- `on_export_start` / `on_export_end`

集成实现位于 `utils/callbacks/`：TensorBoard、W&B、MLflow、Comet、ClearML、HUB、Ray Tune 等。
